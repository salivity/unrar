Force Unrar to Extract Files Despite CRC Errors

When a RAR archive suffers from partial corruption or an incomplete download, the extraction utility typically halts the process and deletes the damaged output due to a Cyclic Redundancy Check (CRC) failure. However, you can instruct unrar to ignore these integrity failures and preserve the unpacked data anyway. This guide explains how to bypass default deletion behavior using the command-line interface as well as graphical alternatives to recover usable data from corrupted archives.

The -kb Switch in the Command Line

By default, the unrar command-line utility purges any file that fails the CRC check to prevent corrupt data from remaining on your filesystem. To prevent this deletion, you must pass the -kb (Keep Broken) switch in your terminal command.

To extract the archive while preserving directory structures and keeping damaged files:

unrar x -kb archive.rar

To extract all files directly into the current directory without maintaining the original folder paths:

unrar e -kb archive.rar

How the Command Works

  • x: Instructs the utility to extract files with their full relative paths.
  • e: Instructs the utility to extract files directly into the working directory, flattening the folder structure.
  • -kb: Tells the extractor to keep broken extracted files. The terminal will still output a CRC error warning, but the resulting file will not be deleted upon completion.

Using WinRAR (GUI Method)

If you are using the graphical version of WinRAR on Windows, you can achieve the exact same result:

  1. Right-click the .rar file and select Extract files... to open the extraction path and options dialog.
  2. Under the General tab, locate the Miscellaneous section in the lower-left corner.
  3. Check the box labeled Keep broken files.
  4. Click OK to begin extraction.

When the CRC error message appears, close the notification window. The extracted files will remain in your destination folder.

What to Expect from Recovered Files

Forcing an extraction does not repair the corrupted data; it only retains the parts that were successfully unpacked.

  • Media Files (Video and Audio): Often playable up until the point of corruption, or entirely playable with modern media players (such as VLC) that skip damaged blocks.
  • Text and Document Files: Usually partially readable up to the point where data was lost.
  • Executables, Databases, and Disk Images: Rarely functional, as binary and structured files typically fail to launch or mount if even a single byte is missing.
