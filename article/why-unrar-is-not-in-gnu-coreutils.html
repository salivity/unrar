Why unrar Is Not in GNU Coreutils

The utility unrar is excluded from the default GNU coreutils package primarily due to software licensing restrictions and the specific architectural scope of coreutils. While coreutils provides fundamental system utilities like cat, ls, and cp, archiving tools are traditionally managed as separate software packages. Furthermore, because the RAR format and the official unrar source code are governed by a proprietary, non-free license, the software cannot be distributed under the GNU General Public License (GPL) that governs GNU coreutils and most base Linux distributions.

1. Functional Scope of GNU Coreutils

GNU coreutils is designed to provide only the bare-metal, core utilities required for basic file, shell, and text manipulation on a POSIX-compliant system. Coreutils includes basic commands such as rm, mkdir, chmod, and echo.

Archiving and compression utilities have never been part of the coreutils package. Even standard open-source tools such as tar, gzip, bzip2, and xz are maintained and packaged independently from coreutils. Expecting unrar to be included in coreutils fundamentally misunderstands the package's intended scope.

2. Proprietary Licensing of the RAR Format

The primary barrier preventing unrar from being integrated into standard base systems is licensing. The RAR compression algorithm was developed by Eugene Roshal and is maintained by win.rar GmbH. The source code for the official decompression tool (unrar) is made publicly available, but it is not released under an open-source license.

The official unrar license explicitly forbids anyone from using the decompression algorithm to reverse-engineer or recreate the RAR compression algorithm. This restriction violates the core definitions of Free and Open Source Software (FOSS) maintained by the Free Software Foundation (FSF) and the Open Source Initiative (OSI). Because the GNU project adheres strictly to the GPL, proprietary software cannot be packaged into GNU coreutils or bundled in the default installations of standard Linux distributions.

3. Separation of Free and Non-Free Software

Because of its non-free license, most Linux distributions relegate the official unrar utility to restricted, non-free software repositories (such as Debian's non-free or Ubuntu's multiverse). Including proprietary software in the default base system would compromise the distribution's commitment to delivering purely free software out of the box.

4. Available Alternatives

Users who need to decompress RAR archives on Linux have two primary routes:

  • The Non-Free Official Utility: Users can manually enable non-free repositories to install unrar.
  • Reverse-Engineered Free Tools: Utilities like unrar-free or unar (The Unarchiver) provide free-software decompression functionality, though they may lack support for newer RAR5 archive formats due to the legal and technical challenges of reverse-engineering proprietary compression algorithms.
