Unrar Licensing Restrictions for Distribution

Before distributing the unrar utility or its source code, developers and system administrators must navigate several critical licensing constraints. Although the source code for unrar is publicly accessible and free to download, it is distributed under a proprietary, non-open-source license written by Alexander Roshal. Key restrictions include an explicit prohibition against reverse-engineering the RAR compression algorithm, incompatibility with standard copyleft licenses like the GNU General Public License (GPL), and strict stipulations regarding redistribution in commercial environments.

The Non-Free Nature of the License

The unrar license is neither Open Source Initiative (OSI) approved nor compliant with the Debian Free Software Guidelines (DFSG). While it grants permission to view, compile, and distribute the unrar code for decompression purposes, it fails the standard definition of Free and Open Source Software (FOSS) because it places deliberate limits on how the software may be used and studied. Consequently, major Linux distributions package official unrar binaries in restricted or "non-free" repositories rather than their core distributions.

Prohibition Against Re-Creating the Compression Algorithm

The most critical clause in the unrar source license is the restriction on reverse-engineering the compression engine:

  • No Compression Development: The license explicitly states that the source code may not be used to re-create the RAR compression algorithm, reverse-engineer it, or create third-party tools that generate RAR-compatible archives.
  • Decompression Only: Derived works and modifications are strictly restricted to expanding, extracting, and decompressing RAR archives.

Distributing software that uses modified unrar code to write or modify RAR archives constitutes a direct violation of the author's intellectual property rights.

Incompatibility with the GPL and Copyleft Licenses

Because the unrar license imposes restrictions on modification and usage that go beyond the permissions granted by the GNU General Public License (GPL), the two licenses are legally incompatible.

  • Static or Dynamic Linking: You cannot link unrar source code directly into a GPL-licensed application and distribute the resulting binary. Doing so breaches the GPL's requirement that no additional restrictions be placed on the downstream user.
  • Separation Requirements: Projects that require both GPL code and RAR extraction must either invoke the standalone unrar executable via an external sub-process or use an independently written, clean-room reverse-engineered alternative such as unrar-free (which only supports older RAR formats).

Commercial Redistribution Considerations

Distributing compiled binaries versus integrating the source code carries distinct requirements:

  • Unmodified Binaries: Distributing the official, unmodified unrar binary alongside commercial software as a standalone utility is generally permitted under freeware terms, provided the original copyright notice and license documentation remain intact.
  • Bundling and Integration: Embedding unrar code directly into proprietary commercial applications or altering it for integration requires strict adherence to the copyright notice conditions. If custom integration blurs the line between standalone decompression and unauthorized implementation of RAR technologies, explicit licensing permission must be obtained from the copyright holder.

Copyright and Attribution Requirements

Any legal distribution of unrar—whether as source code or a compiled binary—requires retaining all original copyright notices, the author's name (Alexander Roshal), and the full text of the license agreement. You may not claim authorship or remove the disclaimer of warranty.
