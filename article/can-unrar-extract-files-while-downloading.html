Can Unrar Extract Files While Downloading?

The short answer is no; standard unrar cannot natively stream and extract a single archive incrementally as it downloads byte-by-byte. Because the RAR format generally requires random access (seeking) to read headers, file tables, and compressed data blocks, the command-line utility cannot process an incomplete data stream via standard input. However, you can achieve partial or volume-based incremental extraction under specific conditions, particularly when dealing with multi-part RAR archives.

Why Incremental Extraction Fails on Single Archives

The official unrar utility does not support reading archives directly from standard input (stdin). Formats like tar are strictly linear and can be piped directly into an extractor while downloading. In contrast, RAR archives—especially RAR5 format or solid archives—store metadata, dictionary states, and checksums that require the extractor to navigate back and forth throughout the file. If unrar attempts to read an incomplete, actively downloading file, it will crash or terminate with an unexpected end-of-file (EOF) error once it reaches the portion that has not yet downloaded.

Incremental Extraction with Multi-Volume Archives

The closest practical solution to incremental extraction is using multi-part archives (.part01.rar, .part02.rar, etc.). If you are downloading a segmented archive, you do not always need every single volume to extract early contents:

  1. Self-Contained Files: If an individual file within the archive begins and ends completely inside part01.rar, it can technically be extracted before part02.rar finishes downloading.
  2. Missing Volume Behavior: When unrar reaches a file that spans across to a missing part, it will prompt for the next volume. If the next volume is unavailable, the process will pause or fail.

Using the Keep Broken Files Flag (-kb)

If you must extract whatever data is available from an actively downloading or partially complete archive, you can use the -kb (Keep Broken) switch:

unrar x -kb archive.part01.rar /target/directory/

By default, unrar deletes any partially unpacked or corrupted files when an extraction fails due to missing volumes or an unexpected EOF. The -kb flag overrides this behavior, forcing the utility to save any completely extracted files and keep whatever partial data was decoded before encountering the missing bytes.

Automated Alternatives

If your goal is to extract contents automatically as downloads finish, standard practice is to decouple downloading from extraction:

  • Archive-Aware Download Managers: Tools like JDownloader, SABnzbd, or NZBGet manage downloads sequentially and trigger extraction scripts automatically only when a complete archive or the necessary sequential volume has finished verifying.
  • Stream-Friendly Formats: If you have control over the archive creation, use uncompressed tar or zip with linear compression, which allows piping directly from tools like curl or wget into standard extraction utilities.
